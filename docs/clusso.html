Algorithm one

CLUSSO

Regression on a matrix-valued predictor whose first mode is unbalanced: each subject contributes a different number of rows.

Algorithm one

CLUSSO

Subject i contributes a matrix-valued predictor Xi of size pi×q. The two modes behave differently, and that asymmetry is the whole problem. The first mode is unbalanced: subject i supplies pi objects, and that count varies freely from one subject to the next. The second mode is balanced: the same q features are measured on every object, for every subject. The outcome yi is a single continuous scalar.

This shape breaks every existing scalar‑on‑matrix method, because those methods require identical matrix dimensions for every subject. There are really two problems here. First, the matrices are unbalanced: they have different numbers of rows. Second, the rows are unordered, so object 7 in one subject has nothing to do with object 7 in another. Clustering solves both problems at once. It also preserves variation between objects that plain averaging would erase.

This structure is common in biomedical data. Anywhere a subject yields a variable number of measured units, each described by the same fixed panel: cells per sample with the same genes assayed on each, events per sample in flow cytometry with the same markers, segmented objects per image with the same morphology features, lesions per patient with the same radiomic descriptors. The method below never inspects what an object is.
{ Xi ∈ ℝpi×q , yi ∈ ℝ : i=1,…,n }

The row count varies by subject and the rows carry no shared ordering. The columns are the same q features for everyone.

  1. 1

    Pool

    Every object from every subject goes into one matrix. The clustering is not done per subject. It has to be global, so that “cluster 1” means the same thing for every subject.

    𝕋∈ ℝ (∑ipi) ×q

    For a cohort of 250 subjects averaging 900 objects each, measured on 57 features, that is roughly 225,000 × 57.

  2. 2

    Cluster

    A Gaussian mixture model with G=2 assigns every object a label. The only formal assumption is that objects are drawn from a two‑component latent mixture; the components need not correspond to any pre-labelled grouping.

    Tji ⟶ label ∈ {1,2}

    This step is unsupervised. It never sees the outcome.

  3. 3

    Average and reweight

    Collapse the objects within each subject and within each cluster. The weights are each subject’s share of objects in that cluster. This matters because the composition of a subject — what fraction of their objects falls in each population — is often itself the quantity that carries signal.

    X^ i,k ∗ = ∑j=1pi 𝟙(Tji∈𝕋^k) Tji ∑j=1pi 𝟙(Tji∈𝕋^k)

    Row k of the cluster‑averaged matrix: the mean of subject i’s objects assigned to cluster k.

    w^ki = 1pi ∑j=1pi 𝟙(Tji∈𝕋^k)

    The observed share of that subject’s objects assigned to cluster k.

    X^ i ∗∗ = diag ( w^1i , w^2i ) X^ i ∗ ∈ ℝ2×q

    The design is balanced at last: two rows for every subject, whatever their object count.

    Why this matters. When the two populations differ on a feature, the distribution of that feature across all objects is bimodal. Averaging over all of them flattens the distribution and returns a number that describes neither population.
  4. 4

    Structured lasso

    This model uses two coefficient vectors instead of one. α applies to the rows, which are clusters, and β applies to the columns, which are features. The fit alternates between the two, because the objective is bilinear and therefore not convex.

    yi= α⊤ X^i∗∗ β + εi
    arg min 1n ∑i=1n ( yi− α⊤ X^i∗∗ β ) 2 + λn ‖β‖ 1

    Subject to ‖α‖1=1 and a fixed sign on the largest component of β. Both constraints exist for identifiability.

    repeat up to 50 times
    fix α: Z=α⊤X^∗∗ n × q
    β←lasso(Z,y;λ)
    fix β: W=X^∗∗β n × 2
    α←OLS(W,y)
    until ‖ β⊗α − β0⊗α0 ‖ <0.01
    λ chosen by 5‑fold cross‑validation non-convex → 5 random restarts, keep best objective
    Only β is penalized. The paper departs from Zhao & Leng deliberately here. Both clusters must stay in the model, so α is left unregularized. Selection therefore always applies to features, never to clusters.
S= { j : β^j ≠0 }

The selected feature set. This is the only quantity PS‑Fdr needs.

A worked example

Everything below was produced by running this repository’s own estimator, Mainfunction_albet.py, on a cohort small enough to print in full. Objects are drawn from two latent populations. Population 1 centres near (2, 10) on the two informative features and population 2 near (6, 2). Measurement noise of σR=0.3 was added to every object.

The third feature is the one to watch. It varies from subject to subject, but it takes an identical value in both populations and has no effect on the outcome. It is a pure nuisance variable, included deliberately so we can check whether the lasso removes it.

α∗= (1,3) β∗= (2,−1,0) σ=0.5

The truth being recovered. Population 2 counts three times as much as population 1, and feature 3 has no effect at all.

Follow one row across. Subject A’s four population-1 objects average to (1.90, 10.03, 4.91). Multiplying by w₁ = 0.80 gives row 1, (1.52, 8.03, 3.93). That is the only place the weights are used. They are applied once, here, and then absorbed into the numbers. Note that every figure is shown to two decimals while the arithmetic runs at full precision. So 0.80 × 10.03 gives 8.02 by hand, where the row shows 8.03 computed from the unrounded 10.0334.
Now compare the third number in the two cluster-mean columns: 4.91 against 4.92, 6.66 against 6.66, 5.07 against 5.07. The nuisance feature takes the same value in both populations for every subject. It carries no cluster structure at all, which is exactly why it should be dropped. Features 1 and 2 behave differently, separating cleanly at about 1.9 against 5.9 and 10.0 against 2.0.
The last two design columns hold the same values. row₁ + row₂ equals the naive average for every subject, to machine precision. The largest discrepancy across all 12 subjects and 3 features is 1.78e‑15. The two rows partition the naive vector. This is an algebraic identity, not a coincidence.
yi= (α∗)⊤ X^i∗∗ β∗ +εi εi∼ N(0,0.52)

The last column, y, is the continuous scalar outcome being predicted. It is the target, not part of the design. For subject A, row₁ + 3·row₂ = (5.12, 9.28, 6.88). Taking the dot product with β∗=(2,−1,0) gives 0.96. The observed value of 0.20 is that figure plus a noise draw of −0.76. Feature 3 contributes nothing, because β3∗=0.

Sorting that column by w₂ shows it climbing almost monotonically, from 0.20 at 20% population 2 to 24.20 at 83%. This is not chance. With α∗=(1,3) the population-2 row counts three times as much. Composition drives the outcome: the larger a subject’s share of population-2 objects, the larger their response.
⋅ Inside the lasso: standardizing before the penalty

Before any penalty is applied, Z=α⊤X^∗∗ is z‑scored column by column across the twelve subjects. The raw columns differ in spread by more than a factor of two, and an L1 penalty is not scale‑invariant. Without this step, lambda would penalize the narrowest column most heavily, purely because of its units.

Reading the middle column downward shows what lambda really is: a dial. Raise it and false discoveries fall away. Raise it further and real features start disappearing too. The naive lasso sits at 57.5% false positives. CLUSSO matches that figure exactly at λ=0.10, and at that setting CLUSSO is the weaker of the two. In this example CLUSSO buys its lower false positive rate only by accepting a much higher miss rate.

That is not what the paper reports, and the gap is worth naming. Twelve subjects and three features is far smaller than the simulation study, which uses 300 to 2,000 subjects and 10 to 200 features. CLUSSO’s advantage is also reported to grow as the number of features increases. An example this small demonstrates the mechanism, not the comparative performance.

Still, consider what the dial implies. Someone has to choose a point on that curve. Cross‑validation chooses it by minimizing prediction error, which is a criterion with no connection to how many of the selected features are real. Nothing in the table lets you ask for a set that is at most 10% false.

Filling that gap is what the second algorithm exists to do.
